# Technical approach

## Reference and scope

The requested inspiration is Globle’s guess → proximity feedback → repeat loop. The reference website was requested read-only from the cloud environment but the network proxy returned HTTP 403, so live inspection was unavailable. The user’s detailed specification supplies the interaction requirements. Somewhere has its own visual design, copy, icons, and color palette; no reference-site code or assets are used.

The first release is a single-player random-round game with country/capital/flag modes and separate saved rounds: no accounts, daily challenge, timers, leaderboard, audio, or infrastructure. The globe is the visual centerpiece; search and history sit alongside it on desktop; on phones, search appears above the globe and history below it. The screen is personalized with a compact “Built for Val” title and heart. Submitting a guess scrolls the mobile globe into the center of the viewport and triggers a short, delayed rotation and logarithmic zoom interpolation to the guessed country. Country area from the bundled metadata determines automatic zoom (1.3×–16×); keyboard and pinch allow 1×–32×. Capitals center the city and use their country’s area. Reveals use the same framing. SVG paths are clipped to the viewport to limit geometry at high zoom. Area-based framing is approximate for elongated or scattered countries; small-country markers cover missing boundary detail. After the final camera frame, the focused guess blinks three times in its heat color using finite CSS animations, then returns to its steady color. Capital and tiny-country markers blink too. The cue is keyed by ISO country ID, applies to guesses and explicitly revealed answers, and waits for the final projected camera frame to be displayed rather than using an independent delay. New focus requests or manual controls cancel old motion and blinking. Reduced-motion preferences skip both effects. Results stay inline, and correct answers start a full-screen celebration immediately at submission, while globe movement and its later green blink run independently. Correct guesses and revealed answers use green. There is no idle animation apart from the loading indicator.

## Stack decision

| Option                          | Benefits                                                                                                                          | Costs / decision                                                                                                                                                         |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| React + TypeScript + Vite       | Clear component and state boundaries; types for country identities and rounds; small static build; good browser-test tooling      | React has a runtime cost, but is useful for synchronized search, history, globe and dialog state. Selected.                                                              |
| Plain TypeScript                | Less UI runtime                                                                                                                   | More manual UI and focus-state coordination for this component-rich game. Viable, but not preferable here.                                                               |
| D3 Geo + SVG orthographic globe | Accurate geographic clipping, topology support, touch and keyboard controls without WebGL, inspectable vectors, no idle rendering | Shaded globe rather than true 3D; projects paths in a bundled Web Worker during camera changes. Offscreen culling and one in-flight request keep work bounded. Selected. |
| react-globe.gl / Three.js       | True 3D lighting, camera controls and GPU rendering; useful for richer scenes                                                     | Adds a larger rendering stack, WebGL/GPU requirements and lifecycle complexity. More than this game needs.                                                               |
| MapLibre flat map               | Familiar pan/zoom and strong mapping ecosystem                                                                                    | Tile/style/service setup is unnecessary for a one-screen globe, and offline boundary coloring still needs data decisions. Not selected.                                  |
| Plain CSS                       | No styling runtime or configuration beyond Vite; responsive layout is easy to inspect                                             | Requires maintaining design tokens and selectors. Selected instead of a utility framework.                                                                               |

React, React DOM, D3 Geo, TopoJSON client, and tree-shaken Lucide icons are the application dependencies. Data-processing, TypeScript, Vite, and test tooling are development dependencies. Lockfile installation and a successful production build verify compatibility in Node 24; supported runtime requirements begin at Node 22.12.

## Boundaries between modules

1. Generate a checked-in 195-country list with one documented selected capital/government-seat point per country from `world-countries`, plus simplified 50m Natural Earth topology from `world-atlas`. Do not fetch gameplay metadata from a live service.
2. Keep alpha-3 IDs canonical in game state. Join map features by ISO numeric code. Keep names exclusively for display and search.
3. Keep Haversine, shared-land-border adjacency, temperature thresholds, distance ranking, duplicate checks, win detection and saved-state validation in pure functions.
4. Let the app display one round and preserve separate country, capital and flag rounds. Flag rounds show a bundled country flag SVG, search country names with suggestion flags hidden, and save an optional continent hint without consuming a guess or ending the round. Persist IDs, mode, reveal state, and answer in versioned browser storage; migrate version-1 country saves without changing guesses or answer. Giving up ends a round without winning or adding a guess; derive distances from validated metadata, rather than trusting stored distances.
5. Pass guessed countries/city points to the globe. Pass an answer location only after an explicit give-up reveal and use a green answer marker without adding a winning guess. Globe taps never select or submit a guess; all guessing uses the search interface. History interactions focus already-guessed countries.
6. Use native modal dialogs for focus containment and Escape support. Offer a complete keyboard search path and text/symbol temperature labels.
7. Build static assets and verify both root and project-subdirectory serving before documenting deployment.

## Accuracy and privacy

Adjacent guesses receive the hottest feedback independently of distance, using an explicit symmetric ISO alpha-3 land-border graph (including documented overseas mappings and data corrections). History sorts by center distance and highlights/pins the closest entry without changing saved chronological guess order. Center-to-center Haversine meets the requested rule and stays consistent for archipelagos and disconnected countries, but it differs from nearest-border distance. Metadata centers can be approximate and need not be inside every component. Natural Earth boundaries are generalized and make specific choices in disputed areas. This game does not settle geopolitical questions; the explicit UN-plus-observers answer list and all data limitations are documented in the README and in-game guide.

A browser-only game can keep the answer out of visible UI and out of the globe’s inputs, but cannot keep it secret from developer tools. A serverless answer/guess service could improve secrecy later, at the cost of an API, round/session handling, abuse controls and hosting quotas. That is unnecessary for this personal project.

## Cost and hosting

Cloudflare Pages is the recommendation: connect Git, build with `npm run build`, publish `dist`, and share its HTTPS `pages.dev` URL. There are no API keys, map requests to third parties, paid assets, or mandatory custom domains. Free hosting is subject to the platform’s current limits. GitHub Pages and Netlify are compatible alternatives. An optional GitHub Pages Actions workflow is included, but nothing is published by running the local build.

## Validation and performance approach

- Unit tests exercise known distances, identical coordinates, antipodes, poles, the date line, temperature boundaries, aliases, country ID uniqueness, duplicate prevention, exact-match wins, round stability and invalid saved data.
- Browser tests exercise actual production assets at desktop and Pixel 7 viewport sizes. They cover the full game and map behavior, errors and retry, and accessibility checks. Phone emulation does not replace a physical-device or Safari test.
- Initial production JavaScript is about 102 kB gzipped; the separately loaded globe module is about 15 kB gzipped, plus a 25 kB uncompressed bundled projection worker. CSS is about 5 kB gzipped. The simplified boundary asset is approximately 623 kB uncompressed and is fetched once per globe mount with normal browser caching. These are build measurements, not claims about slow-device frame rates or network latency.
- No continuous animation, imagery, fonts, or render loop runs while the globe is idle. Rotation projects the existing simplified geometry in a Web Worker. Conservative spherical bounds skip invisible countries (tested against the atlas at date-line, polar and close-up views), a viewport-sized clip limits close-up geometry, and path coordinates use one decimal place in the 600-unit SVG. Only one worker request is in flight; intermediate camera positions are dropped in favor of the newest position. Country paths, ocean radius, graticule and city markers use the same returned camera. The arrival blink waits for the final returned frame, while celebrations start immediately on the main thread. Worker failure falls back to synchronous projection without disabling gameplay. Search stays usable while map loading is pending or fails.
- There are no development-only answer controls in the shipped application. Tests seed local storage externally. Before a correct guess or explicit give-up reveal, browser checks assert the answer’s map fill remains neutral (the flag image is the intended clue in Flags) and only submitted countries/capitals are marked. Tests verify reveal states never award wins, round history is preserved, and switching modes does not discard either round.

Real hosting credentials and publication remain with the user. The README describes a repeatable deployment, but no claim of a deployed URL or successful fresh-cloud snapshot is made.

Flag images: copy only the 195 playable 4:3 SVGs from the pinned MIT-licensed `flag-icons` development dependency into `public/flags`, named with canonical ISO alpha-3 IDs. The shared image component respects the Vite base URL for repository-subpath hosting; search suggestions in Flags omit images. The mystery image has a neutral accessible label until completion, and a failed image has a retry control that preserves the round and hint. Country/capital suggestions, all history rows, and result screens also use these SVGs. No external flag CDN, emoji font, new paid service, or runtime package is required.

Victory effects: a shared shuffled bag selects confetti, fireworks, an emoji parade, heart fountains, shooting stars or rainbow bubbles on a fresh correct guess, with all six used before refilling and no adjacent repeat across bags. The 4.8-second canvas mounts at the app root as a fixed viewport-sized overlay, leaving the answer and globe visible without a result popup. Each fresh win adds an effect to a FIFO queue independent of round/mode state. The win submission enqueues the effect immediately, with no globe callback, readiness gate or flight fallback timer. History refocusing cannot enqueue another celebration. The queue head stays keyed by its sequence across restarts, guesses and mode changes; further wins wait their turn and play for their full duration. It is decorative and ignores pointer events. It allocates at most 100 particles on phones or 160 on desktop (28/42 for emoji), caps device pixel ratio at 1.5, and uses one requestAnimationFrame loop with no per-frame React updates. Cleanup cancels the frame and removes listeners. Animation age accumulates only during visible, motion-enabled playback. Tab visibility or a live reduced-motion change pauses requestAnimationFrame without completing the effect; returning resumes the remaining time. Wins made with reduced motion already enabled stay static. The transient queue is cleared only on completion or page teardown, not by gameplay actions; refresh does not replay old wins. Reveals and completed-result refocusing do not create new effects. Browser tests sample actual nontransparent pixels outside the globe for each effect on desktop and mobile, verify full-viewport bounds and immediate start before any globe movement or blinking, and exercise full-duration playback across gameplay actions, FIFO sequencing, visibility/motion pause-and-resume, and clickable controls. No new runtime dependency or service is used.

A local Chromium Pixel 7 emulation with 4× CPU throttling compared the same correct guesses (France, Singapore and Japan), confetti effect, and 1.9-second observation window before and after background projection. Main-thread script time fell from 1.14–1.22 seconds to 0.38–0.43 seconds. During the 350–1,250 ms camera interval, sampled frame counts rose from 9 to 25–36 and the 95th-percentile frame gap fell from 233–283 ms to 67–83 ms. These are local diagnostic samples, not a fixed frame-rate guarantee or real-phone measurements; SVG painting still costs time on slower devices. No boundary data or celebration duration was reduced.

The title heart is an accessible 44px button with a 650ms long-press threshold. Pointer capture supports touch/mouse holds; early release, canceled pointers, movement beyond 12px, losing focus and hidden tabs cancel a pending hold. Holding Space or Enter works too. Once activated, four finite CSS heartbeat cycles accompany a circular background reveal from the heart’s viewport position, with a viewport-relative radius of 150vmax covering the diagonal even from a corner. The fixed layer extends to the large viewport height (100lvh, with a 100vh fallback), and the origin is clamped inside the layer. Coverage adapts through browser-bar changes, keyboard dismissal and orientation changes without restarting the animation or running JavaScript resize handlers. The heart turns pale as the theme’s accent fills the background to keep it distinct. A fixed decorative portal below the game uses the shared logo-accent CSS variable and never captures input. It fills, briefly rests and fades over 3.6 seconds, then its timer removes the layer and resets the button. Timers are cleaned up on unmount. Reduced motion replaces heartbeat and expansion with a static 20% tint for the same short duration. The effect is independent of round state and the winning-effect queue, adds no dependency, and uses no JavaScript frame loop. Search questions and the extra closest-distance summary are removed; search retains a screen-reader label and history retains its closest badge. The visible globe toolbar is removed; drag, pinch and keyboard exploration remain available.

The header now contains the brand and an outlined sun/moon appearance button. Help is available in the footer; new journeys start from the completed round after a correct guess or give-up reveal, so the early-restart control and confirmation dialog are removed. Light and dark palettes share semantic CSS properties for surfaces, borders, feedback text and controls. The globe retains its geographic feedback colors. On the first visit the theme follows `prefers-color-scheme` (including live changes); an explicit choice is stored under `somewhere.theme.v1` and takes priority. A small inline head script applies that preference, native color scheme and mobile theme-color before the application bundle loads. Storage failures fall back to device preference and leave the toggle usable for the current page. Theme changes do not remount the globe, change rounds or interrupt queued celebrations. Dark-mode tests cover autocomplete, hints, help, revealed results, contrast/accessibility, persistence, blocked storage, keyboard operation and uninterrupted wins.

Dark-mode interface accents use mint green (#62e99a), a softer variation of the requested #4ef589. The shared accent controls the logo tile and dot, title/footer hearts, heartbeat glow, background wave, primary buttons, hover states and dialog accents. The logo glyph uses dark ink for contrast on mint. The browser-tab icon switches to a bundled green SVG with the chosen theme. Disabled buttons use muted green, and the heartbeat’s highlight is pale mint. Light mode keeps its warm palette. Geographic heat colors, flags, and semantic error/warning colors retain their meanings.
