# Somewhere

A small, polished collection of games, built for Val. **Somewhere** offers countries, capitals, flags, shapes and land-connected border journeys on an interactive globe. **Something** offers General Trivia with hot streaks and perfect-round celebrations, plus the five-clue guessing game What am I. **Someone** offers Who am I, a five-clue game about 80 well-known people, and Identify Me, a portrait guessing game with the same 80 people. **Somehow** is a branching geography/trivia adventure with hearts, supplies and a final boss.

**React + TypeScript + Vite, with an SVG globe powered by D3 Geo. Statically hosted on GitHub Pages, with optional Google sign-in and Firebase statistics sync. Guest play needs no account. No analytics or runtime map APIs.**

## Run locally

Use **Node 24.12+** and npm.

```sh
npm ci
npm run dev
```

Open the address printed by Vite. To run and check the deployable build:

```sh
npm test
npm run build
npm run preview
```

The `dist/` directory is the complete website. Keep its `assets/` and `data/` directories together. Do not open `index.html` directly from the filesystem; use a web server.

In the Codex cloud machine, npm’s default home cache is unavailable. Use `npm --cache /tmp/wep-app-npm ci` there. No secrets or environment variables are needed by the app.

## Accounts, statistics and daily check-ins

The header shows the signed-in Google profile picture to the left of the daily flame/count, plus a hamburger menu that slides out from the right. The circular picture comes from Firebase Authentication’s existing Google profile; no extra permissions or API are required. Missing or failed images show initials, and signing out removes the avatar. Press the same header button, tap outside the drawer or press Escape to close it. The menu includes theme selection, update checks, **Your statistics**, **Sign in with Google**, and **Sign out**. The launch update notice still appears automatically. Playing needs no account, but statistics and daily check-ins require Google sign-in. Selecting statistics or the flame while signed out opens the sign-in view. Guest statistics are never recorded or imported; old guest statistics caches are removed. Signed-in data is cached separately for each account; signing out returns to untracked guest play without showing that account's statistics.

Tap the flame to claim a check-in once per day. A ready flame pulses gently; claiming sends a short heart/star sparkle and **+1 day**. The check-in period runs from **noon to noon in America/Chicago**, including daylight-saving changes. Noon makes another claim available; it does not erase an unbroken streak. Missing a full period resets the current streak to zero, while the longest streak stays recorded. Opening the app or signing in alone never claims a day. Reduced-motion preferences replace movement with static feedback.

Statistics are recorded only while signed in, on a valid guess, answer or reveal. Stable round IDs prevent refreshes from adding duplicate plays. The Overall view includes total plays, completions, wins, submitted guesses, trivia accuracy, daily streaks and a weighted average guesses per solve. The By game view includes individual mode plays, completions, wins and average guesses on wins; trivia includes accuracy, best answer streak and perfect rounds; Somehow includes wins and furthest stop. Guess averages include solved country/capital/flag/shape and name/clue rounds, excluding active or revealed rounds. Overall averages weight every solved round equally, rather than averaging mode averages. Border Journey shows average crossings separately; trivia and adventures never dilute guess averages. Overall wins include perfect trivia rounds. A dash means there is no eligible result yet. These totals are derived from existing synced records and need no new Firebase rules or data migration. Reveals and abandoned adventures count as completed without a win. Old completed rounds are not imported retroactively. Actual saved game progress remains device-local; **only statistics and check-ins sync**. Local pending writes survive refreshes, synchronize after reconnecting, and pause during winning celebrations. Signed-in offline check-ins sync when possible; this is a personal trust-based app, not an anti-cheat leaderboard.

### Clue, hint and Border Journey records

New standalone game records optionally include cluesShown for What am I/Who am I/Identify Me, hintUsed for Flags/Shapes, and shortestCrossings for Border Journey. Details are captured with guesses/reveals; revealing a clue or continent after a tracked guess updates that existing record without creating a play just for requesting help. Statistics show average clues and first-clue wins, continent-hint-free wins, and optimal-route counts plus average extra crossings. Identify Me reports zero or one **text** clues and portrait-only wins; its initial image is not counted as a text clue. These insights also appear in the admin player's per-game statistics.

Only eligible solved rounds with those details enter the new averages. Old records keep their existing wins/guess counts and contribute no invented clue/hint/route data. Reveals and active rounds do not enter solve averages. A valid detour remains a win: the result shows either **Optimal route** or its extra crossing count; route generation still requires five or more Africa–Eurasia crossings with no artificial upper cap. Somehow keeps its existing overall-run statistics rather than adding each embedded trial as a separate game.

The updated firestore.rules accepts and validates these optional fields while retaining legacy records, existing check-ins, and admin permissions. Clue counts/hint usage cannot decrease, and the starting shortest-route length cannot change once recorded. Publish the exact updated rules before deploying this version; production rules were published by the project owner during Batch 2. Re-publish future rule changes separately from GitHub Pages.

### Firebase configuration

The public web configuration in `src/lib/firebaseApp.ts` identifies project `web-app-53618`. It is not an administrative credential. Never add a service-account key to the repository. No Analytics SDK is initialized. The client uses Firebase Authentication (Google provider) and Cloud Firestore; there is no custom server or Cloud Function. These services have free-tier quotas; keep the project on Spark for a hard no-billing setup and monitor usage in the Firebase console.

For a fresh project:

1. Register a Firebase web app, update its public configuration, enable **Authentication → Google**, and add your hosting hostname (for this site, `dlc-diego.github.io`) to authorized domains.
2. Create Cloud Firestore in production mode and publish the exact contents of [`firestore.rules`](firestore.rules) in its Rules tab. These rules allow authenticated users to access only their own records, validate fields and counters, and make daily check-ins immutable. They were published for the current project during setup. Future edits to this file **must also be published**; the GitHub Pages workflow does not deploy Firebase rules.
3. Deploy the normal static build. No GitHub secrets, private keys, custom domain, Firebase Hosting or paid plan is required.
4. On a real phone, sign in from the menu, allow the Google popup if prompted, claim the flame and check the statistics on another device. iPhone Home Screen and Safari storage may be separate, so sign in in each installation where you want sync. Popup blocking/cancellation or unavailable cloud access leaves local games playable.

The security rules and SDK synchronization are tested against local Firebase emulators with fake users, including account isolation and duplicate-day protection. This does not establish that the real Google consent flow works on every Safari/Home Screen version; verify that flow on the devices used to play. Daily timekeeping follows the device clock; rules reject future cloud check-ins beyond a small clock-skew allowance. Cloud personal records can be removed by the project administrator; the client never deletes synced history.

## How it plays

- Use the **header wordmark dropdown** to switch between **somewhere.** (geography), **something.** (General Trivia and What am I), and **someone.** (Who am I and Identify Me), and **somehow.** (adventure). The word “some” uses the main text color; “where”, “thing”, “one”, and “how” use the theme accent. Someone initially opens Who am I, remembers your selected mode, preserves your saved games, and uses the same switch animation and theme controls. Its people bank is lazy-loaded; opening Someone first does not load the globe, trivia pack or What am I bank. A brief full-screen accent sweep, turning compass and content fade accompany switching. Reduced-motion preferences switch immediately; enabling that preference during a transition finishes it immediately too. Your selected experience is saved locally, with a safe fallback when browser storage is unavailable. Geography rounds, search input and globe view stay intact when switching; celebrations continue uninterrupted. Opening a saved Something page loads no globe data until you visit Somewhere. No additional service or dependency is required.

- Open the header’s **hamburger menu** and use **Light mode / Dark mode** for light or dark mode. The first visit follows your device’s preference; your choice is saved in this browser and applied before the page paints on future visits. Dark mode covers search, history, dialogs, hints, errors and loading states, with readable heat labels and the same globe feedback colors. Dark-mode accents use mint green (`#62e99a`), including the logo, hearts, buttons and the softer green heart-wave background.
- The hamburger menu’s **Check for updates** action checks for the latest deployed app. If the current build matches, it briefly says **You’re up to date**; otherwise it opens fresh app files. The update action is muted when no update is detected and green when an update is available, in either theme. The hamburger also shows a green notification dot. An eight-second message below the header announces an available update on launch, returning to the app, or reconnecting; the green menu indicator remains afterward. Automatic checks never reload a game, are limited to once per minute (except reconnects), and fail quietly offline. A manual failure offers a retry; checks time out after eight seconds. An update waits for all queued winning celebrations to finish, then reloads with a fresh HTML URL and content-hashed JavaScript/CSS. Saved rounds, trivia answers, mystery clues, selected modes and theme stay in local storage; the update does not clear website data or iOS system caches. This feature becomes available to an existing Home Screen install after it first loads a release containing the update button. Each build emits its matching `version.json`; deploy that file with the rest of `dist/`. No service worker, external update API or paid service is required.
- Choose **Countries**, **Capitals**, **Flags**, **Shapes**, or **Border Journey** in the dropdown above the search field. Each mode keeps a separate saved round, so you can switch without losing any journey. A random answer is selected once per round, and new rounds exclude that mode’s immediately previous answer. Country saves from the earlier version are migrated automatically.
- In country mode, search a name, ISO code, or alias such as `UK`, `UAE`, `Turkey`, or `Ivory Coast`. In capital mode, search a city name or spelling variant such as `Paris`, `Washington DC`, or `Kiev`; suggestions include the city’s country. Select a suggestion, then press **Make a guess**. With a keyboard, Enter selects the highlighted suggestion; a second Enter submits it.
- In **Flags**, identify the displayed flag image by guessing a country name or alias. Suggestions hide their flag images to avoid giving away the match. The globe, distances, heat, duplicate protection, closest-first history, reveal, and green answer animation work as in Countries. **Hint: reveal continent** shows a continent without using a guess, marking the map, or ending the round. The clue remains visible through refresh and mode switches, and resets with a new flag round. Used continent hints remain visible after completion.
- In **Shapes**, identify the country from its silhouette. The outline stays north-up and scales to fit the card, keeping islands and disconnected regions from the source together. **Hint: reveal continent** gives a clue without consuming a guess or ending the round. Shapes has its own saved answer, guesses and hint; the existing distance feedback, adjacency, globe animation, history, reveal and victory effects work as in Countries. Image errors offer **Try shape again** without losing progress.
- In **Border Journey**, travel from the visible starting country to the visible destination, crossing one shared land border per turn. Search and select the next country, then press **Cross the border**. Non-neighboring countries and the current country are rejected without consuming a crossing. Retracing your steps is allowed, so a detour cannot trap you. The chronological journey list and dashed globe route track your actual travels; tap any stop to refocus. The **Destination** button above the travel list centers the destination on the globe without consuming a crossing or ending the round. The current stop uses the theme accent, visited countries blue, and the destination gold until reached or revealed in green. Center-to-center arcs are a schematic guide, not literal border crossing locations. Routes are generated from an undirected border graph with a shortest starting distance of at least five crossings within Africa–Eurasia, with no upper difficulty cap; disconnected islands are excluded. Finishing shows your crossing count and the shortest possible starting route length, without requiring an optimal route. **Give up and reveal answer** shows one shortest continuation from your last stop on the list and globe, ends the round without a celebration, and keeps your original route. Journey progress saves separately, including revisited countries. Invalid stored routes are rejected. A 1,000-crossing guard prevents oversized saves; at that limit, reveal the route to start another journey.
- Drag the globe to rotate it and pinch to zoom up to 32×. Map taps never select or submit guesses; all guesses go through the search interface. Keyboard users can focus the globe and use arrows, `+`, `-`, and `Home`.
- Each guess colors its country and displays the great-circle distance to the answer. Country and flag modes use representative country centers; capital mode uses the two cities’ coordinates and adds a marker for every guessed capital. Text labels and symbols supplement color.
- Cold: **7,000 km or more**. Cool: **3,000–6,999 km**. Warm: **1,000–2,999 km**. Hot: **under 1,000 km**. Countries sharing a land border—and capitals belonging to those countries—are marked **Adjacent** with the hottest, darkest-red feedback regardless of center distance. This does not count as a correct guess. Thresholds use unrounded distances; displayed kilometers are rounded.
- In the mystery modes, only an exact country or selected-capital match wins. A tiny nonzero distance is displayed as `<1 km`.
- In the mystery modes, guess history is sorted by unrounded distance for the selected mode, closest first, with original guess numbers preserved. The closest row has a highlighted background and a “Closest guess” badge; it stays pinned while the desktop list scrolls. Distance ties keep the original guess order. Tap a history entry to center it on the globe. Duplicate guesses are rejected. On phones, search sits above the globe; submitting a guess closes the keyboard and smoothly centers the globe on screen. After a short pause, the globe glides to your guess and zooms based on country area: smaller countries get a closer view, larger ones retain regional context. Automatic zoom ranges from 1.3× to 16×; manual controls reach 32×. Capital guesses use the area of their country while centering the city. Only after that movement finishes, the guessed country and any capital/tiny-country marker blink slowly in their heat color three times (about four seconds), then stay solid. A new guess, manual rotation, or resetting cancels the previous cue. Reduced-motion preferences skip both movement and blinking. Correct guesses and revealed answers blink green. Correct answers launch their victory effect immediately when submitted, independently of the globe’s movement and green blink; no result popup opens.
- **A heart for Val:** hold the heart next to “Built for Val” for about two-thirds of a second. It beats, then a warm wave spreads from the heart across the background in the logo’s accent (orange in light mode, mint green in dark mode) and fades back after a moment. Release after it starts and it will finish on its own. Keyboard users can focus the heart and hold Space or Enter. Short taps and canceled holds leave the game alone. Reduced-motion preferences use a still, subtle tint.
- The **Give up and reveal answer** button is below the guesses and above the footer. It ends the current mode’s round, reveals the answer on the globe in green, and preserves the guess history. The reveal uses the same size-aware zoom. After the globe arrives, the answer and its marker blink three times, then stay green. It does not add a winning guess or count as a win, and it works before any guesses. Other modes are unaffected.
- Correct guesses in all five Somewhere modes get one of six full-screen victory effects: **Confetti shower**, **Fireworks**, **Emoji parade**, **Heart fountains**, **Shooting stars**, or **Rainbow bubbles**. A shuffled bag shared across modes uses all six before reshuffling and prevents an immediate repeat at the boundary. Effects begin immediately on a correct guess (or as soon as an earlier queued effect finishes), last 4.8 seconds of visible playback, and leave controls clickable. Wrong guesses, give-up reveals, refocusing a history row, and refreshing a completed game do not launch effects. Starting another round, resetting the map, switching modes, making guesses or earning another win does not cancel or restart an active celebration. Additional wins queue and play in order, each for its full duration. Globe loading, rotation, zoom and blinking never delay or cancel the celebration. Hiding the tab pauses playback until you return; enabling reduced motion during an effect pauses it until motion is allowed again. Players who already prefer reduced motion when guessing correctly get the static win screen. The transient queue ends when the page is refreshed or closed; saved rounds remain intact. Emoji parade uses standard celebration/heart/globe emojis, with no flag emoji dependency.
- A completed round keeps the answer, guess count, replay controls, and copy-result button on the page, without a popup. Finish by guessing correctly or revealing the answer, then choose **Explore another round** to begin a new journey. **How to play** is in the footer.
- All five Somewhere rounds, all guesses, the selected mode, and revealed/completed states are saved in this browser’s `localStorage`. Invalid saves recover with a message. If storage is disabled or full, gameplay continues with a warning. Progress is local to the browser and is not synced between devices or tabs.

### Something games

**General Trivia** has ten questions per round, four choices each and no timer. Choose once, read the explanation, then press **Next question**. The current question, shuffled choices, score and feedback survive refreshes. A sidebar records answers; expand an entry to review its question and explanation. The score screen offers **Play another round**. The bundled pack currently contains 400 original-worded questions, with 40 in each of ten categories: animals, space, science, food and drink, history, arts and books, film and music, nature, the human body, and games/everyday things. Stable general-knowledge facts are used rather than current rankings or breaking news; the pack is manually maintained, so factual corrections can be made in `src/data/trivia.ts`. No external trivia API, account, paid service or runtime content request is required.

New General Trivia rounds are balanced: one question from each of the ten categories, in shuffled order. **Round difficulty** offers **Standard mix** (all 400 questions) or **Harder questions** (100 curated questions, ten per category). Every question has a standard/hard editorial tag in the data; the choices are relative to this pack, not a measured skill rating. The hard selection is maintained in src/data/triviaDifficulty.ts. Changing the selection before the first answer replaces the untouched round; changing it after an answer applies to the next round, preserving current questions, score and celebrations. Existing saved rounds keep their original questions and choice order.

Each category uses a local shuffle cycle within the selected difficulty pool. A category refills only after all its eligible questions have been allocated, and the immediately previous round is excluded when refilling. Standard and harder selections retain their own cycle histories, so switching pools does not erase progress in either; a question may appear in both pools. The current round, cycles, and next-round preference persist through refresh. Legacy saves without difficulty/cycle fields remain readable. None of this synchronizes seen-question history across devices.

Correct answers use the six existing celebrations until three consecutive correct answers. At **3+**, the sidebar says **On Fire** and correct answers launch **Fire streak**: fire emojis rise across the screen with progressively greater count, size and speed on each streak continuation. Counts range from 28 to 56 on phones, or 42 to 84 on desktop, over streaks 3–10. A wrong answer resets the count to zero; the next correct answer returns to the usual six effects. A new round also resets the streak. A **10/10 perfect round** additionally queues **Perfect round**, a golden starburst with expanding rings and a trophy, after the final answer's fire effect. All celebrations share the same queue as Somewhere: 4.8 seconds of visible playback per effect, no cancellation on new rounds, wrong answers, mode switches or experience switches. Already queued effects finish even after a wrong answer resets the current streak. Reduced-motion preferences keep results static; existing hidden-tab and live reduced-motion pause/resume apply to fire and trophy effects too.

**What am I** starts with one clue about an animal, object, structure or natural phenomenon. **Reveal another clue** uncovers progressively clearer clues, up to five, without spending a guess. Type an answer and press **Make a guess**; capitalization, accents, punctuation, leading articles and listed aliases are normalized. Wrong guesses remain visible and do not end the mystery. Duplicate normalized guesses are rejected. **Give up and reveal answer** remains below the guesses; it reveals the solution and all clues without creating a win or celebration. A correct answer uses the usual six celebrations. After solving or revealing, **Try another mystery** starts a different answer. There are 80 original five-clue mysteries in `src/data/mysteries.ts`. Clues may intentionally fit several things at first; later clues narrow the intended answer. Specific aliases are accepted rather than unrestricted fuzzy matching.

Text-answer modes (What am I, Who am I, Identify Me, and their Somehow trials) now offer conservative spelling assistance. A unique likely misspelling with one insertion, deletion, substitution, or adjacent transposition can prompt correction without recording a guess, spending an attempt, changing hearts/supplies, or accepting the answer as correct. Short inputs and ambiguous matches do not trigger it, and an exact valid answer elsewhere in the catalog still counts as an ordinary guess. Matching checks the full mode catalog rather than just the secret answer, and the prompt never supplies a candidate name. Saved historical guesses are not reinterpreted.

Each Something mode has an independent saved session (`something.trivia.v1`, `something.mystery.v1`) and shares `something.mode.v1` for the selected mode. Sessions validate question IDs, choice permutations, answer counts, clue bounds, aliases and terminal states before loading. Damaged saves recover only the affected mode with a notice; storage failures leave games playable with a warning. New rounds prioritize unseen content and exclude the immediately previous question set or mystery; content eventually repeats after the finite local pack is used. Both modes retain their UI state when switching experiences. Opening Something first does not load the globe, and Something's question/clue module is lazy-loaded when first visited. Answers are bundled in a static app and can be inspected; this is a private, trust-based game rather than an anti-cheat system. **How to play** in the footer explains the selected experience.

### Someone — Who am I

Choose **someone.** in the header to play **Who am I** immediately. The first collection contains **80 distinct real public figures**, with ten each in science and mathematics, music, screen and stage, sport, art and literature, history, exploration and invention, and changemakers. Original clue sets and short explanations live in `src/data/people.ts`. Who am I uses text clues only; no paid APIs or external trivia service are required. The clues focus on public achievements and become more specific as you reveal them.

Start with one broad clue, reveal up to five progressively clearer clues for free, and type a name. Full names and curated aliases (such as Einstein, Beyoncé, Pelé or The Rock) accept case, accent, punctuation and spacing variations. Some unique surnames and commonly used nicknames are accepted; unrestricted fuzzy matching and ambiguous first names are not used. Wrong guesses remain visible without ending the game, and normalized duplicates do not count twice. **Give up and reveal answer** sits below the guesses and reveals the person, explanation and all clues without a celebration. Correct guesses immediately use the existing six winning animations. **Try another person** starts a fresh mystery; new rounds prioritize all unseen people before recycling and never immediately repeat the last person.

Progress saves independently under `someone.who.v1`, including the person, guesses, clues, completion and seen-person history. Switching experiences retains an unfinished name in the input. Invalid saves recover only Who am I with a notice; blocked storage leaves the game playable with a warning. Refreshing a completed round never replays a celebration, and queued celebrations continue through new rounds or experience switches. The footer’s **How to play** explains this experience. Who am I and What am I share the tested clue-game engine in `src/lib/mystery.ts`; their content and saved sessions stay separate. Somehow uses these same people for Who am I and Identify Me trials, alongside the original What am I collection, with independent adventure progress.

### Someone — Identify Me

Choose **Identify Me** in the Someone game dropdown. Name the person shown in a photograph, painting, engraving or sculpture. The collection covers the same **80 people** as Who am I. Historical artworks can be later or disputed representations rather than verified likenesses. **Reveal a clue** supplies one optional text clue for free, and guessing continues. The usual name aliases, duplicate checks, guess history, immediate winning effects, give-up reveal and replay apply. The portrait is contained without adding a crop. A failed image or manifest offers a retry without resetting progress.

Identify Me saves separately under `someone.identify.v1`; the selected Someone mode uses `someone.mode.v1`. Who am I and Identify Me retain their rounds and unfinished input when switching. Opaque filenames and neutral alternative text do not name the answer before completion; legally required credits and source pages may do so. Original images can contain contextual details such as name badges. Like the other static modes, developer tools can inspect the answer. Visual recognition cannot be made equivalent through neutral alternative text; the text-only Who am I mode remains available.

**Image sources and licensing:** All 80 bundled images were retrieved from [Wikimedia Commons](https://commons.wikimedia.org/), with each file's own licensing metadata checked. Commons is the source, not a blanket license. This pack uses only explicit public-domain statements, CC0, CC BY or CC BY-SA. Unsupported, noncommercial, no-derivatives, GFDL-only and unclear licenses are rejected by the importer. Each image displays its creator and license link, and **Image credits** opens its title, creator, original Commons file page, rights statement, source credit, additional attribution and transformation notes. Adapted CC BY-SA images remain under their respective source licenses. Image licenses do not relicense the app code. Public figures are used for identification, without implying endorsement; copyright licenses do not grant personality or endorsement rights.

The complete, per-image attribution is in [public/portraits/CREDITS.md](public/portraits/CREDITS.md), also linked inside the game. Each `portrait-NNN.source.json` retains the Commons API licensing snapshot and retrieval date. `manifest.json` records the source URL, creator, license, transformations, dimensions and SHA-256 hashes. Images are resized to at most 640×800 and converted to WebP, with orientation corrected when needed and no extra crop or generative changes. Source files may themselves already be cropped. The 80 images total only a few megabytes; the app fetches the manifest and current image when this mode is visited, not the entire collection. No Wikimedia requests, hotlinking, API key or paid service is needed during play.

The committed images are used by routine builds. To review or deliberately regenerate the collection:

```sh
python3 -m pip install -r scripts/requirements-portraits.txt # optional importer only
python3 -m unittest discover -s scripts -p 'test_portrait_import.py'
npm run portraits:import  # requires access to Wikipedia, Commons and upload.wikimedia.org
npm run portraits:verify # verifies all 80 image hashes, source receipts and credits
```

The roster in `scripts/data/portrait-roster.json` pins each selected Commons file. Successful imports are cached outside the repo in `/tmp/somewhere-portrait-import-cache`; use `--cache-dir` with a new empty directory to recheck the latest source metadata. The importer publishes nothing unless every entry passes. Review all regenerated images and licensing records before committing them. The deployment workflow runs the asset/credit verification gate before building. Python/Pillow and network access are unnecessary for normal app builds or CI.

### Somehow adventure

Choose **somehow.** in the header to play immediately. No password, account, backend or paid service is required.

A run has **thirteen stops**, displayed as a 31-node branching map. The map is divided into three expandable sections: **First steps** (stops 1–4), **The middle path** (5–8), and **The final stretch** (9–13). The current section opens by default, while completed and upcoming sections can be expanded for inspection. All three-by-three choices and valid connections remain intact; finishing a gate or the midpoint rest automatically focuses the next section when you return to the route. Each of the three route sections has three rows of three choices. Only highlighted, connected nodes can be selected. Choose between normal challenges, shops, discoveries and harder elite trials; one guaranteed rest stop occurs at stop eight. Stops four and twelve are now a trivia gate and an elite gate. Clear the final boss at stop thirteen to win. Starting hearts: **2/2**; maximum containers: **5**. Rest stops restore one heart without raising the maximum. A run ends when the last heart is lost without a Phoenix feather, or when the final battle is abandoned. The completed/failed stop stays on screen; use **Return to the route** to continue. Rewards cannot be collected twice.

- **General Trivia:** answer all three questions correctly. A failed trial risks one heart, rather than charging for every wrong answer.
- **Elite trial:** three correct answers in a row. **Final boss:** four in a row. Each wrong answer resets the streak and risks one heart. Read each explanation before continuing; no timer is used.
- **Countries, Capitals, Flags, Shapes:** the existing search, aliases, distances, adjacency feedback, guess history, country images and interactive globe, with five guesses per encounter. All 195 playable countries can appear, including small and very large countries. Exact correct guesses clear the encounter; exhausting the budget or giving up reveals the answer and risks one heart. Guesses are never made by tapping the globe.
- **Border Journey:** the existing mainland-only border graph, with an initial Africa–Eurasia route at least five crossings long and no upper difficulty cap and a budget of the shortest starting route plus one spare crossing. ## Data, accuracy, and licensing

- **Playable list:** 195 entries: 193 UN member states plus Palestine and Vatican City. This is an explicit gameplay scope, rather than a statement about sovereignty. Dependent territories and other disputed states, including Taiwan and Kosovo, are not answers in this version. The guide explains this scope before play.
- **Metadata:** [mledoze/countries](https://github.com/mledoze/countries), provided by `world-countries`. Each playable country has a canonical ISO 3166-1 alpha-3 identifier. Names and useful aliases are normalized for case, diacritics, punctuation, and whitespace. The two Congos have distinct display names.
- **Adjacency:** Shared land borders are generated from `world-countries` ISO alpha-3 border lists, made symmetric, and restricted to playable countries. Explicit territory mappings include French Guiana/Saint Martin → France, Sint Maarten → Netherlands, Gibraltar → United Kingdom, and Hong Kong/Macau → China. Canada–Denmark’s 2022 Hans Island land border is added; the source’s one-sided India–Sri Lanka entry is removed because Palk Strait is not a land border. Sea crossings and maritime borders alone do not count. The graph follows source border claims elsewhere and is independent of simplified map geometry.
- **Shapes:** All 195 silhouettes are generated offline from the per-country GeoJSON outlines in the existing `world-countries` dependency, credited to [mledoze/countries](https://github.com/mledoze/countries) and its thematicmapping.org boundary source. They use a north-up local azimuthal equal-area projection, corrected exterior winding and a 0.25-pixel projected simplification tolerance. Every island remains represented; disconnected regions are not rearranged or resized separately. Each country is scaled to the same card size, so shape size is not a clue to land area. Tiny atolls may be difficult to identify. Generalized, historical outlines and overseas-territory choices can differ from the globe (for example, the France silhouette emphasizes European France and Corsica rather than French Guiana). Disputed boundaries follow the upstream dataset. The adapted path database is downloadable at `public/shapes/outlines.json`, with attribution and the ODbL license beside it. Run `npm run data:shapes` to regenerate just these images, or `npm run data:generate` for all geographic assets. SVG clues are self-hosted and fetched one at a time; no shape API or map-rendering work runs during gameplay. Accessible image labels remain neutral until completion; this is a visual recognition game, and the same browser-only answer-privacy limits apply.
- **Flags and continent hints:** Flags use bundled 4:3 SVG images from [flag-icons](https://github.com/lipis/flag-icons), pinned as a development dependency and copied to `public/flags/<ISO-alpha-3>.svg` by the data generator. Only the 195 playable images are included, with the upstream MIT license in `public/flags/LICENSE.txt`. Images load from the same static site, not a third-party CDN or API, so they display independently of device emoji support. A failed challenge image offers a retry without resetting the round or hint. Some flags (such as Chad and Romania) remain very similar; only the exact country wins, and continent/distance clues can help. Screen readers get a neutral “Mystery flag” label until completion so the accessible name does not disclose the answer; this remains a visual recognition game. Continents follow the metadata’s region classification, with the Americas split using subregion: South America stays South America; Central America, the Caribbean and North America use North America. Oceania is the regional continent label. Transcontinental countries use one classification (Russia → Europe; Türkiye → Asia); overseas territories do not change the hint.
- **Capitals:** One selected capital/government seat per playable country, using representative public-domain Natural Earth populated-place coordinates joined to canonical country IDs. Choices include Pretoria (South Africa), Sucre (Bolivia), Amsterdam (Netherlands), Mbabane (Eswatini), Sri Jayawardenepura Kotte (Sri Lanka), and Ramallah as Palestine’s administrative seat. Yaren is Nauru’s government district, not an official capital, and uses a documented approximate point. Other co-capitals are not separate answers; aliases refer to the same selected city. The source can lag relocations (for example Jakarta follows the source during Indonesia’s transition). See [capital source notes](scripts/data/README.md) for the full policies, source details, and exceptions. City markers identify actual city points rather than country centers.
- **Boundaries:** Natural Earth 1:50m via [world-atlas](https://github.com/topojson/world-atlas). Country features are joined through zero-padded ISO numeric codes and then matched to alpha-3 records; names are never used for matching. MultiPolygon features preserve disconnected regions. Some dataset IDs repeat across associated regions; rendering uses separate feature keys while matching all their parts to the same country.
- **Rendering:** The generator simplifies topology, preserving shared borders and disconnected polygon records. Outlines are approximate and small islands may be visually reduced or degenerate at this scale. Tiny guessed countries receive a center marker; Tuvalu, which has no boundary in this dataset, always receives one. Before guessing, tiny countries can be selected reliably through search.
- **Disputes:** Borders reflect the source dataset’s choices and vintage. Areas without a matching numeric code remain neutral and unplayable. Claims, overseas dependencies, and disputed areas are not reassigned by inference from their labels.
- **Centers and distance:** Metadata supplies representative latitude and longitude, which are not calculated land centroids, capitals, or nearest border points. The same coordinates are used consistently for all guesses and answers. Large or island countries can produce unintuitive center distances; overseas regions do not change the chosen center. Haversine uses mean Earth radius **6,371.0088 km**, handles the date line and poles, and clamps floating-point error. The Earth is treated as a sphere.
- **Licenses:** Natural Earth geography is public domain; the `world-atlas` package has an ISC license. Country metadata is ODbL. The adapted metadata database is distributed under ODbL at `public/data/countries.json`, alongside the complete license. Flag images are MIT-licensed; their attribution and full license are shipped with the site. Original sources and download links are credited in the game guide. No assets, branding, or code were copied from Globle.

Generated datasets are committed, bundled, and served from your site. Updating npm dependencies does not silently change geography. To deliberately update them:

```sh
npm run data:generate
npm test
npm run build
```

Review the resulting data changes and attribution. `scripts/generate-data.mjs` is deterministic and validates list membership. Routine builds use committed data and do not need to regenerate it.

## Architecture and trade-offs

See [docs/technical-plan.md](docs/technical-plan.md) for the library comparison and implementation choices.

```text
src/
  lib/            Country lookup, geographic math, game rules, saved-state validation
  components/     Globe, accessible country/capital search, guess history, native dialog
  data/           Playable countries, selected capitals, and border metadata
  App.tsx         Round state and the game screen
  styles.css      Responsive plain CSS and reduced-motion support
public/data/      Lazy-loaded boundaries, adapted metadata, attribution licenses
scripts/          Reproducible dataset preparation
tests/            Browser tests using production assets
```

**Answer privacy:** The globe receives guesses and only receives the answer location after the player explicitly gives up; correct guesses already appear in the guess list. It does not pan to or mark an answer before a correct guess or giving up. However, a fully static game must calculate distances in the browser, so the answer exists in memory and saved storage. A player using developer tools can find it. Obfuscation would not solve this. Strong secrecy requires a server to hold the answer and evaluate guesses; that complexity is intentionally avoided for this personal game.

**Performance:** Country boundaries and D3 are loaded separately from the initial game UI. Search works while the map loads and after map failures. Geometry is simplified ahead of time. A bundled Web Worker projects country outlines away from the UI thread, skipping offscreen shapes and obsolete camera frames. Paths, markers and ocean zoom update together, and the heat blink waits for the final displayed frame. If workers are unavailable, rendering falls back to the main thread. There is no animation/render loop when idle, and no remote imagery or web fonts. Victory effects use a short-lived canvas with a capped pixel ratio and particle count; no animation runs after the effect completes. SVG is a shaded orthographic projection with 3D-like rotation, not a WebGL 3D scene. Current measurements and limits are recorded in the technical plan.

Once GitHub Pages is configured to use GitHub Actions, pushes to `main` automatically rebuild and deploy the site. The deployment workflow reports its published URL. A local build alone does not publish the app.

Zoom framing uses an area-based estimate, not a guarantee that every island or elongated border fits on screen. Zooming magnifies the bundled Natural Earth boundaries; it cannot add detail absent from that data. Tiny-country markers remain visible, and reset restores the full globe. Manual zoom cancels an active flight or blink.

### Border Journey geography

Border Journey uses the same ISO alpha-3 country IDs and `world-countries` border metadata, with a separate reviewed mainland-only filter in `src/data/journey-border-exclusions.json`. Generation, submitted crossings, shortest-route reveals and saved-route validation all use this one filtered graph. Every new route stays within connected **Africa–Eurasia**, uniformly selected from all start/destination pairs whose shortest valid path requires **at least five crossings**, excluding the previous destination. The Americas are not selected for new journeys. There is no artificial upper difficulty cap: the finite mainland border graph determines the longest possible shortest route. The starting country is not a crossing: five crossings means entering five countries after it, including the destination. These selection rules apply to new rounds; saved shorter or Americas journeys remain playable so an update does not discard progress. The same selection applies to new Border Journey trials in Somehow, with their existing shortest-route-plus-one crossing budget. Europe–Asia and Egypt–Israel crossings remain possible because they do not require an ocean jump; North America–Europe routes are impossible.

The mode treats each country as one primary connected land area: European France, mainland Spain, Great Britain, mainland Russia, mainland Azerbaijan, mainland Angola, the main connected Croatian area, peninsular Malaysia and Java for Indonesia. It excludes overseas borders (Canada–Denmark through Hans Island, France–Brazil/Suriname through French Guiana, France–Netherlands through Saint Martin, Spain–Morocco through Ceuta/Melilla, Spain–UK through Gibraltar), borders requiring detached exclaves (Kaliningrad, Nakhchivan, Cabinda and the Dubrovnik coastal area), Northern Ireland links and Borneo/New Guinea/Timor island shortcuts. Indonesia has no eligible border on Java, so it is not selected for journeys. Malaysia uses a journey-only point at 4.2° N, 102.1° E on its peninsula for camera focus, markers and route arcs, replacing its usual Borneo-centered point only in this mode. Other modes retain their existing political adjacency feedback. Existing journey saves that depend on excluded crossings or disconnected endpoints recover to a fresh journey with the standard warning; other saves are preserved.

Borders along rivers and canals are still land borders; sea bridges, tunnels and ferries do not create new graph edges. The displayed arcs join representative country centers and are schematic, not literal walking directions. Border claims follow the source metadata, and this remains a geographic puzzle rather than a claim about legal or practical travel access. Review the exclusion list whenever updating the source border data.

## Admin panel

The hamburger menu shows **Admin panel** only for a signed-in Firebase UID with an enabled admin membership. This is a small support tool: player lookup, read-only overall/per-game statistics, recent check-ins, upward streak credits with confirmation, and the latest 25 administrative adjustments. It contains no statistics-reset feature and never changes saved game rounds.

### One-time Firebase setup

These steps require the Firebase project owner in the console; the public web app configuration cannot administer a project. No service-account key, custom backend, Cloud Functions, new dependency, or paid plan is required.

1. In [Firestore Rules](https://console.firebase.google.com/project/web-app-53618/firestore/rules), replace the rules with the complete contents of [`firestore.rules`](firestore.rules) and **Publish**. The existing player rules remain compatible. Do not switch to test mode.
2. In [Firestore Data](https://console.firebase.google.com/project/web-app-53618/firestore/data), create the top-level collection **`admins`**. Create document **`fpHgEWnCWWUq9n3G53BXI9LboCd2`** (the owner's Google account UID) with the field **`enabled`**, type **boolean**, value **`true`**. Do not use a string or put this document inside `users`. Verify the UID against Authentication → Users before granting access.
3. Open the updated app, sign in to that Google account, and open the hamburger menu. **Admin panel** should appear. To revoke access, set `enabled` to boolean `false` in the console. The panel closes when the app receives the change. No browser client, including an admin, can create or change membership documents.

An update that has not yet received the new rules simply hides the panel; existing gameplay and statistics sync remain available. Reopen the app after publishing the rules if it was already open. Players are registered in the private `players` directory when they open this app version while signed in. Search uses a full, case-insensitive email address or Firebase UID; blank search lists the 20 most recently registered/refreshed players. A UID also works for older accounts that already have game/check-in records, even before their directory entry exists. A UID with neither a profile nor saved data is rejected to reduce accidental credits to mistyped accounts.

### Crediting missed streak days

Select a player, enter a higher desired current streak (up to 365 days), add a reason, and choose **Preview adjustment**. Check the player's UID, current → proposed streak, longest streak, and missing-day count, then confirm. Cancel performs no writes. Credits fill only missing check-in dates and preserve all existing check-ins, longest streak history, statistics, and rounds. If today has not been claimed, the credit ends yesterday, leaving today's flame available. If bridging a gap would connect a longer historical streak, the preview asks for that actual total rather than silently overshooting it. Dates follow noon America/Chicago, including DST.

The check-ins and their `adminAudit` entry are written in one online transaction; they either all succeed or none do. Changes to the affected check-ins during confirmation invalidate the preview. A stale preview after noon must be refreshed. Offline adjustments fail without changing local or cloud records. Admin-created check-ins cannot be overwritten or deleted, and rules require a new matching audit entry for every credit transaction. Audit entries are immutable through the web app. Credits sync through the existing check-in listener to the player's online devices; an older offline device sees them on reconnect. Do not manually edit an existing check-in to lower a streak, because the app's history merges assume immutable days.

The directory's email/name and every player's statistics/check-ins are readable only by their owner or an enabled administrator; directory and audit list queries have explicit small limits. Admins can read game records but cannot alter another player's game statistics. Profile writes are restricted to the signed-in UID and verified token email; they cannot grant privileges. The directory stores no Google tokens or passwords. Firebase reads/writes still count toward the existing free-plan quotas: a streak credit reads roughly the desired streak length and writes one document per missing day plus one audit entry. This is intended for occasional private support, not bulk administration. Full game history is read when selecting a player, which is suitable for this small app but would need pagination at larger scale.

Admin security is covered by the Firestore emulator tests, including unauthorized/disabled accounts, role escalation, spoofed profile emails, unaudited credits, immutable audit history, and the maximum 365-day transaction. The account emulator browser suite covers confirmed/canceled credits, cross-device results, offline failure, unchanged game statistics, access revocation, and mobile accessibility. These tests use only `demo-somewhere` and never adjust production accounts.
